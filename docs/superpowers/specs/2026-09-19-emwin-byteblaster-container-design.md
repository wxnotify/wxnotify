# EMWIN Byteblaster Container — Design

Source: master plan (`wxnotify-nextgen-plan.html`: FEAT "Downloader control", DATA "EMWIN ingestion stays two-path", ARCH Pipeline service split). This spec adds the Byteblaster (primary EMWIN) feed client as its own Docker Compose service, alongside the existing `nwws` container. The EMWIN HTTP-backup client is a separate, later piece and stays a static "status unknown" row.

## Goal

A Docker service, `emwin`, built around the open-source **Npemwin** (Tcl) daemon, that downloads EMWIN products from community-run Byteblaster servers and delivers each text product to the Laravel pipeline by API call, where it is ingested exactly like an NWWS product — with cross-feed de-duplication so a product arriving on both feeds is ingested once.

## Decisions (user-approved)

- **Delivery:** shared volume + path, mirroring NWWS. npemwind writes to a volume also mounted in Laravel; the pan script POSTs only the relative file path.
- **Role of EMWIN:** a full second feed with cross-feed dedup (whichever feed delivers first wins), so EMWIN genuinely backs NWWS up.
- **Scope:** container + Laravel endpoint/dedup + Pipeline Control wiring + feed-health heartbeat.
- **Architecture:** the image is multi-arch and selects its `.deb` from BuildKit's `TARGETARCH` (arm64 for local Apple-silicon dev, amd64 for Intel production) — no hard-coded `platform`.
- **Version:** npemwin **3.0.1p1 on both architectures** so dev matches production. Both `.deb` files are vendored in the repo with checksums (noaaport.net currently serves an incomplete TLS chain, so build-time downloads are unreliable): `docker/emwin/packages/npemwin_3.0.1p1-1_arm64.deb` (SHA-256 `006635decab0147de8a786bedce26047da3cc9e49fba7265a89b9954f7923a76`, supplied by the user) and `npemwin_3.0.1p1-1_amd64.deb` (Debian 11 build from `https://www.noaaport.net/software/packages/npemwin-3.0.1p1/packages/debian-11/amd64/`, checksum recorded when vendored) plus a `SHA256SUMS` file the Dockerfile verifies. Bump both together when an arm64 3.1.x exists.
- **Compose service name:** `emwin` (`container_name: wxnotify-emwin`).
- **Product storage:** npemwind stores files under `/var/npemwin/files/text/[cccc]/`. That directory is the shared volume (`emwin-products`), mounted read-only in Laravel. EMWIN products are zipped; every product is delivered from a unique copy under `/var/npemwin/files/text/delivered/` in the same volume (unzipped members, or copies of plain text files), and unzip errors are logged and skipped. Unique copies matter because EMWIN file names repeat across issuances while Laravel keys ingested rows by file path — delivering npemwind's own file would overwrite the previous issuance's row.

## Container (`docker/emwin/`)

- Base `debian:12-slim`; installs the vendored `.deb` (its dependencies come from apt: `tcl`, `tcllib`, `libdb5.3`, `libwrap0`, `gnuplot-nox`, `unzip` — already a package dependency —, `curl`) plus `rsyslog` and `ca-certificates`. The build fails if the `.deb`'s SHA-256 does not match `SHA256SUMS`.
- Runs `npemwind` as the package's unprivileged user (create it if the package doesn't). `/var/npemwin/files/text` is pre-created with that owner so a fresh named volume inherits it; products are world-readable so Laravel can read them.
- Baked-in site configuration under `/usr/local/etc/npemwin/site/`, from the user's own samples:
  - `features.conf` — the user's file (panfilter enabled; the rest at defaults).
  - `panfilter.conf` — the user's file.
  - `panfilter.rc` — calls `/pan-notify.sh $rc(fpath)` for each file received (`lappend cond {1}` + `exec`), with its output going to the console/syslog rather than a file.
  - `/usr/local/etc/npemwin/servers.conf` — a fallback list (the user's sample, one `IP<TAB>port` per line) used until/unless the refresher replaces it.
- **`pan-notify.sh`** (POSIX sh): the per-file hook. EMWIN products arrive zipped, so it handles two kinds of file it is given:
  - **`.ZIP` (any case):** unzips before anything is sent to the pipeline (see "Unzip step" below), then delivers each extracted text product.
  - **`.TXT` (any case, already plain text):** copied to a unique file under `delivered/` and delivered from there (covers the case where npemwind already unzipped it, and any product that arrives unzipped).
  - Anything else (images, other graphics) is ignored — not alertable yet.
  Delivery of one text file: POST `{"path": "<path relative to the shared volume>"}` with the bearer token to `${EMWIN_WEBHOOK_URL}` (default `http://laravel.test/api/pipeline/emwin-products`), `curl -sS -f --max-time 10`; log one line via `logger` (syslog → console); touch `/tmp/emwin-last-product` on success. A failed POST is logged and never aborts npemwind.
- **Unzip step and unique delivery copies.** Every delivered file lives in the same shared volume, under `/var/npemwin/files/text/delivered/<original relative dir>/`, named `<base>_<UTC yyyymmddTHHMMSS>_<pid>_<n>.txt` so no two issuances ever share a path, and Laravel reads it by the same path mechanism (the relative path posted is `delivered/<cccc>/<unique name>`). Rules:
  - Extract with `unzip -j -o -q` (junk paths: a hostile archive cannot write outside the target directory) into a private temp directory first, then move only accepted members into `delivered/` under their unique names.
  - Accept only text members (`*.txt`, case-insensitive); ignore every other member. A zip may contain several members — each accepted one is delivered.
  - Refuse before extracting if `unzip -l` reports a total uncompressed size above `EMWIN_MAX_UNZIP_BYTES` (default 5 MB) or more than 50 members (zip-bomb guard); log and skip.
  - **Errors never stop the pipeline:** a corrupt, truncated, encrypted, oversized or member-less archive is logged through `logger` at error level with the archive path and unzip's own message, its temp directory is removed, and the script exits 0 — "log the error and move on". One bad zip never affects the next product.
  - Delivered files are kept (consistent with NWWS, which keeps its files) and pruned by the entrypoint's maintenance loop after `EMWIN_RETENTION_DAYS` (default 7) so the volume stays bounded; npemwind's own files are left to npemwind's own cleanup.
- **`refresh-servers.sh`** (POSIX sh + curl + awk): fetches `https://weathermessage.net/Support/EMWINInternetStatus.aspx`, parses the static HTML table (columns IP address, server name, port), and writes `IP<TAB>port` per row (using the hostname when a row has no IP). Safety rules: never overwrite `servers.conf` with fewer than 3 valid servers; write atomically (temp file + `mv`); validate each row (IPv4 or hostname, numeric port); on any fetch/parse failure keep the current list and exit non-zero; print a one-line summary. Exit codes distinguish "changed", "unchanged", "failed".
- **`entrypoint.sh`**: starts `rsyslogd` (config `omfile` to `/dev/stdout`, so all syslog output appears in `docker logs`), runs `refresh-servers.sh` once, starts a background loop that re-runs it every `EMWIN_SERVERS_REFRESH_HOURS` (default 6) and — only when it reports "changed" — creates a restart flag and stops `npemwind`, then runs `/usr/local/sbin/npemwind -F` in the foreground. If `npemwind` exits and the restart flag exists, the entrypoint clears the flag and starts it again; any other exit ends the container (Docker's `restart: unless-stopped` handles it).
- **Healthcheck:** `npemwind` process is running and the web interface on port 8016 answers.
- Port `8016` (npemwin's web view of received files) is exposed and mapped in Compose as `${EMWIN_WEB_PORT:-8016}:8016` for admin reference only; nothing in WxNotify uses it.

## Compose (`compose.yaml`)

New service `emwin`: build `context: .`, `dockerfile: docker/emwin/Dockerfile`, `container_name: wxnotify-emwin`; environment `PIPELINE_WEBHOOK_TOKEN`, `EMWIN_WEBHOOK_URL`, `EMWIN_SERVERS_REFRESH_HOURS`, `EMWIN_MAX_UNZIP_BYTES`, `EMWIN_RETENTION_DAYS`; volume `emwin-products:/var/npemwin/files/text`; network `sail`; `restart: unless-stopped`; `depends_on: laravel.test`. The `laravel.test` service also mounts `emwin-products:/emwin-products:ro`. Declare the `emwin-products` named volume.

## Laravel side

- **Route:** `POST /api/pipeline/emwin-products` behind the existing `pipeline.webhook` middleware, handled by `IngestEmwinProductController` (mirrors `IngestNwwsProductController`): validates `path`, resolves it under the new `config('services.pipeline.emwin_products_path')` (`/emwin-products`), rejects traversal/missing files with 404, reads the file, and ingests via the existing `IngestProductText` action with `file_path` = `emwin/<relative path>` (so it can never collide with an NWWS `file_path`).
- **Identity from the product text, not the filename** (EMWIN filenames don't match `IngestedProduct::parseFilename`): a new action `ExtractWmoHeaderIdentity` parses the WMO abbreviated heading (`TTAAII CCCC DDHHMM [BBB]`) and the AWIPS product-ID line from the top of the text, returning `cccc`, `ttaaii`, `awipsid`, `wmo_ddhhmm` and a normalized `wmo_header_key` (`ttaaii cccc ddhhmm [bbb] awipsid`, lowercased, BBB included so amendments/corrections stay distinct). If the header cannot be parsed the product is still ingested (identity fields null, warning logged) but is exempt from dedup.
- **New columns on `ingested_products`:** `source` (string, default `nwws`; `emwin` for this feed) and `wmo_header_key` (nullable, indexed). The NWWS controller is updated to populate `wmo_header_key` from the same action so both feeds are comparable. Existing rows keep null (only new ingests dedup).
- **Cross-feed dedup:** before ingesting, take a short cache lock keyed on the `wmo_header_key`; if a row with that key already exists (from either feed) respond 204 without ingesting (and log at debug). The lock closes the race where both feeds deliver the same product at once. The NWWS endpoint gets the same check so whichever feed is slower is the one skipped.
- **Heartbeat:** every authenticated POST to the EMWIN endpoint, including deduplicated ones, records `last_received_at` for the `emwin` feed in the cache (small `PipelineHeartbeat` helper). Pipeline Control reads it; Pipeline health can reuse it later.

## Pipeline Control

Refactor `App\Filament\Admin\Pages\PipelineControl` from its NWWS-only methods to a small list of managed feeds (NWWS → `wxnotify-nwws`, EMWIN Byteblaster → `wxnotify-emwin`), each with status badge, Start/Stop/Restart via the existing `DockerEngineClient`, and a "last product received" time from the heartbeat. EMWIN HTTP backup remains a static "status unknown" row. Existing NWWS behavior and tests must keep passing.

## Testing

- **Laravel (Pest feature tests):** endpoint requires the bearer token; happy-path ingestion with `source = emwin` and `file_path = emwin/...`; path traversal and missing-file 404; `ExtractWmoHeaderIdentity` against real-shaped fixtures (warning, AFD, plain, with/without BBB, unparseable); dedup both ways (NWWS then EMWIN skipped; EMWIN then NWWS skipped) and that a differing BBB/time is *not* deduped; the concurrent-arrival lock; heartbeat updated on accepted and deduplicated posts; Pipeline Control rows/actions for both feeds with the Docker client faked.
- **Container:** a shell test for `refresh-servers.sh` using a saved copy of the status page as a fixture (parses expected rows; refuses < 3 servers; leaves the file untouched on garbage; atomic write; "unchanged" vs "changed" exit codes), runnable with `sh` without Docker; `pan-notify.sh` tested with a stub `curl` and real small zip fixtures built in the test (valid single-member zip → one POST with the `delivered/...` path; multi-member zip → one POST per text member; non-text members ignored; corrupt/truncated/encrypted zip, oversized total and over-member-count zips → an error line logged, no POST, exit 0, temp dir removed; path-traversal member name cannot escape the target; plain `.TXT` → copied to a unique `delivered/` name and POSTed (two runs on the same source name give two distinct paths); non-TXT/non-ZIP ignored; failed POST doesn't crash; a bad zip followed by a good one still delivers the good one). The image is built for both architectures; an integration run confirms npemwind connects to a live community server, logs appear in `docker logs`, and a received product reaches Laravel.

## Out of scope

The EMWIN HTTP-backup client; EMWIN image/graphics products; the plan's "connected to feed" status layer beyond the last-product heartbeat; running npemwind's own outbound Byteblaster/relay/ldm/nntp features; automatic image/package update checks.

## Verified facts (spike, 2026-09-19)

Run: image built for arm64 (arm64 deb SHA-256 `006635de...7923a76` confirmed; amd64 deb vendored, SHA-256 `8b9cc956ef074e08a0c0dd95e0f41df643a193af2f360bb2ad8c0afbe633925c`). Container ran ~7 minutes against the baked-in `servers.conf` with real network access (`rsyslogd; runuser -u noaaport -- /usr/local/sbin/npemwind -F`). Package version `3.0.1p1-1` (`npemwinversion`).

- **Startup/connection:** starts with our `site/` files and connects. First two servers timed out (`45.33.12.136`, `207.244.226.161`), then `npemwind: Connected to 71.82.31.73 @ 2211`. Files arrived within seconds (17 files in ~2 min). When no server answers it logs `No servers available.` / `Waiting 60 seconds.` and retries the whole list.
- **Where files go:** NOT `/var/npemwin/files/text/`. The output root is `/var/npemwin/files` (`out_dirname` in the `qrunner` script), and text products are `/var/npemwin/files/txt/<cccc>/<prodname>.<md5>.txt` (lowercase, e.g. `txt/kwbc/sahourly.c0b2c402b7b0249deb7ffcfcc46ae9a2.txt`, `txt/kabq/svsabqnm.9412d3256b7c38bcb425ac688d0a9972.txt`, `txt/ktar/ffhtarma.9ee414bdb3d452cdc8e3dbff0c690704.txt`). Non-text products go to `/var/npemwin/files/<ext>/` (radar `rad/<sss>/`, `sat/`); none arrived in the window. The package does not create `files/text`; only our Dockerfile did.
- **Zipped vs plain:** npemwind unzips itself. Its `qrunner` script reassembles parts, runs `unzip -qq -L -o` on `.zip`/`.zis`, and writes each member as plain text (`tr -d '\001\003'` and CR stripped). Every text file under `txt/` is plain `.txt`; no `.ZIP` ever reaches `files/` or panfilter. The `.txt` files start with the WMO heading on line 1 and the AWIPS product ID on line 2, with no SOH/ETX bytes:
  - `FOUS71 KTAR 192045` / `FFHTAR` / `HEADWATER FLASH FLOOD GUIDANCE`
  - `FTUS41 KCLE 192043 AAB` / `TAFCLE` / `TAF AMD`
  - `WWUS55 KABQ 192044` / `SVSABQ`
- **Same name, later issuance:** the file name embeds an MD5 of the content (`detect_duplicates=1`), so a changed issuance gets a NEW file (two `sahourly.*.txt` with different hashes coexisted in `txt/kwbc/`). Identical retransmissions are deleted and NOT sent to panfilter (`qrunner: svsabqnm.123472.txt is retransmitting svsabqnm.9412d3256b7c38bcb425ac688d0a9972.txt.`). Nothing observed was overwritten.
- **panfilter fires** once per new file (`panfilter.rc` is re-sourced per run by the `panfilter` script; edits take effect without restarting). `$rc(...)` variables (from `/usr/local/libexec/npemwin/filters.lib`): `prodname`, `fpath`, `fbasename`, `fseqnumber` (the md5), `ftype` (extension, `txt`), `fsize`, `bodypart`, `HEADER`/`header` (WMO heading line, e.g. `FPUS55 KPUB 192044`), `header_wmoid`, `header_station`, `header_time`, `AWIPS`/`awips`, `AWIPS1`/`awips1`, `txtflag`, `seconds`, `ymdhm`, `yyyy`, `m`, `d`, `H`, `M`, `ymd`, `hm`, `ymd_hm`, `ymd_h`, `ymdh`, `ym`. Sample: `fpath=/var/npemwin/files/txt/kpub/zfppubco.3e3b...88f1.txt prodname=zfppubco ftype=txt fsize=63781 HEADER=FPUS55 KPUB 192044 AWIPS=ZFPPUB txtflag=1`. With our original `rc` and no `/pan-notify.sh`, syslog showed `panfilter: couldn't execute "/pan-notify.sh": no such file or directory` (harmless; proves the hook runs).
- **Process name:** `/usr/local/sbin/npemwind -F` (pid runs as `noaaport`; helper `tclsh8.6 /usr/local/libexec/npemwin/httpd` also runs). `pkill -f 'npemwind -F'` is safe (does not match the httpd helper). SIGTERM logs `Closing processor.` / `Stoped httpd.` / `Stoped.` and exits (status 1 through `runuser`).
- **servers.conf reload:** `kill -HUP` logs `Received hangup signal.` and, only when it arrives while connected, `Reread server list.` and drops the current connection; the new list was used (`Cannot open connection to 192.0.2.1`). A HUP sent while the daemon is in the `Waiting 60 seconds` retry state was NOT reflected in later attempts. Not reliable: keep the stop-and-restart approach.
- **Syslog:** facility `user` (rsyslog default routes it to `/var/log/user.log` and `/var/log/syslog`); idents `npemwind`, `qrunner`, `panfilter`. `rsyslogd` prints `imklog: cannot open kernel log (/proc/kmsg)` in a container (harmless; disable `imklog`/use only `imuxsock` in our rsyslog.conf). npemwind itself also prints one line to stdout at start: `/debug user "debug" password "..."` (a random web-debug credential; not used).
- **Web UI:** `curl localhost:8016` inside the container returns 200 (title `Npemwin@<hostname>`).
- **User/dirs:** `noaaport` uid/gid 1000 already exists after the deb installs (our `id ||` guard is a no-op); the deb pre-creates and chowns `/var/npemwin/{files,data,spool,tmp,www,...}` and `/var/log/npemwin`. Running as `noaaport` needed nothing else (no pid dir). Files are created mode 0644, directories 0755 (world-readable).
- **Retention:** the package's `hourly-cleanup.conf` deletes anything under `/var/npemwin/files` older than 2 days (`-mtime +2`) when its cleanup runs; it was not observed running in this session.

Plan adjustments:
- The shared volume must cover npemwind's real output root. Mount `emwin-products` at `/var/npemwin/files` (not `.../files/text`); Laravel's read-only mount resolves `txt/<cccc>/<file>.txt` relative to it. Update the Dockerfile `mkdir` (drop `files/text/delivered`) and the Compose volume target.
- No unzip step and no `delivered/` unique copies are needed for `.txt` products: npemwind already unzips, and md5-suffixed names never repeat for different content. `pan-notify.sh` should POST the path relative to `/var/npemwin/files` (e.g. `txt/kwbc/sahourly.<md5>.txt`), only when `$rc(ftype)` is `txt` (ignore other types), keep the unzip code only as a defensive fallback if desired, and skip the delivered-copy retention pruning (npemwin's own cleanup handles retention). Task 3/4 and the Laravel `emwin/<relative path>` `file_path` should use the `txt/...` relative path.
- The panfilter hook should pass the `.txt` path only (`exec /pan-notify.sh $rc(fpath)`, or pass `$rc(ftype)` too); the file-name pattern is `<prodname>.<32-hex md5>.txt`.
- The restart approach in `entrypoint.sh` should use `pkill -f 'npemwind -F'` (TERM), not HUP.
