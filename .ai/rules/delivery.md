# Delivery

## Channel delivery goes through ChannelDispatcher; subscriber-controlled URLs go through WebhookUrlGuard and never follow redirects
Every send to a subscriber NotificationChannel must go through ChannelDispatcher (SendActivityAlert is the one exception: it sends to an admin-set ActivityAlertRule::apprise_target). Any URL a subscriber controls — webhook URLs and Web Push endpoints — must pass WebhookUrlGuard both when saved and again at send time, and the HTTP client used to call it must NOT follow redirects (Guzzle follows up to 5 by default and would let a public https URL 302 the server to a private/metadata address). Webhooks get this via config('webhook-server.webhook_job') = NoRedirectCallWebhookJob; restoring Spatie's CallWebhookJob reopens the hole. Web Push builds its own Guzzle client with allow_redirects=false and treats any non-2xx (including 3xx) as failure. Never put an exception message, response body, endpoint URL or key material in a DeliveryResult error: build it from fixed strings plus the numeric HTTP status. apprise_url and config are encrypted and must not be logged. New channel types need a channel_types migration AND a ChannelTypeSeeder::SHIPPED entry in matching sort order. Known open item: the guard's DNS resolution and the HTTP client's own resolution are separate (TOCTOU); pinning via CURLOPT_RESOLVE in the webhook_job subclass is the follow-up.

## Webhook proxy/header guards, no Spatie retries with dispatchSync, and a wall-clock budget for synchronous retries
(1) A webhook channel's proxy_url is subscriber-controlled: it must pass WebhookUrlGuard::proxyViolation() at save AND send time. Its rules deliberately differ from the target URL's (http allowed, credentials allowed, ports 80/443 allowed alongside >=1024) — not an oversight. Extra headers must pass WebhookHeaderGuard at both points too (reserved names incl. Host, Content-Length, Content-Type, Transfer-Encoding, Connection, Upgrade, TE, Trailer, Proxy-Authorization, Proxy-Connection and the configured Signature/Timestamp names). Proxy URL and header values are secrets: like the signing secret and endpoint they must never reach a DeliveryResult error, a log or the activity log. The DNS-vs-client TOCTOU also applies to the proxy host. (2) Never hand Spatie maximumTries() > 1 together with dispatchSync(): the job release()s itself after a failed non-final attempt and returns without throwing, so throwExceptionOnFailure() never fires and the caller records a successful delivery that never happened. Retrying belongs in WebhookTransport's own loop, taking waits through App\Support\Delivery\Pauser so tests bind a recording no-op instead of sleeping. (3) A synchronous transport with subscriber-configurable retries/timeouts needs a wall-clock budget (WebhookTransport::DELIVERY_BUDGET_SECONDS = 50), not just per-attempt bounds: stay under min(queue retry_after, worker --timeout) (90 s / 60 s in config/queue.php) because exceeding retry_after causes a DUPLICATE delivery. Project the next attempt's cost before starting it, and keep in-request sends (confirmation codes) to a single attempt.

## Email channels send through Laravel Mail
The Email channel type uses ChannelTransport::Mail: MailTransport sends App\Mail\ChannelMessageMail (a Markdown mailable, body in an escaped <pre>) through the configured default mailer to the encrypted config['to'], never through Apprise. Failure text is fixed (missing address / mail server could not send): an exception message can carry the SMTP host, credentials or the recipient address. The shared mail theme header (resources/views/vendor/mail/html/header.blade.php) renders the logo from APP_URL plus APP_NAME for every Markdown email, including Filament's; keep custom emails on the Markdown layout so they inherit it. The SMTP mailer timeout is 10 s (MAIL_TIMEOUT) so the synchronous send stays well under the queue worker timeout, per the wall-clock-budget rule above. When `$meta['daily_summary']` is present (a Full Daily Summary for a channel type whose `supportsRichContent()` is true), MailTransport sends App\Mail\DailySummaryMail instead, with the same relay/address checks and fixed failure text; it is still the Markdown layout, with the radar image embedded inline as `cid:radar-snapshot`. DailySummaryMail must be sent, never queued: its constructor registers a closure, so only the plain-data report array travels on the queue. Every other channel type stays on Apprise.
